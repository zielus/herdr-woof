# Architecture decisions

Status: synthesis of the product conversation, 2026-09-14. “Settled” below means
the direction expressed by that source and the current request, not approval of
every detail in a previous assistant-generated draft.

## Settled product direction

| Decision                            | Consequence                                                                    |
| ----------------------------------- | ------------------------------------------------------------------------------ |
| One Woof product                    | Both plugins and the SDK share concepts; orchestration is part of Woof.        |
| SDK owns the engine                 | Gates, retries, validation and run state are reusable outside a plugin UI.     |
| Herdr remains runtime               | Reuse its agent/session/pane/worktree operations and integration capabilities. |
| Agent callers come first            | Rich structured input is primary; manual CLI ergonomics are secondary.         |
| Identity differs from stage         | Repair can reuse the builder; stage changes do not imply new sessions.         |
| Artifacts carry substantive work    | Review files are required; envelopes carry control data and references.        |
| Engine validates results            | Idle state and a completion claim cannot by themselves satisfy a stage.        |
| Every loop is bounded               | Work retries, format repairs, rounds and waits have explicit policies.         |
| Configuration has two scopes        | User defaults and project overrides work independently of Claude Code.         |
| Observability is part of the engine | Snapshots and updates support multiple consumers from the start.               |
| MCP is optional                     | Core invocation and result submission have a non-MCP path.                     |
| TUI later                           | Establish the observation contract now; defer the renderer.                    |

## Superseded recommendations

| Earlier idea                                                | Current resolution                                                                                                |
| ----------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------- |
| Woof is only developer UX; Horde owns loops                 | Woof is the product and `HerdrAgentsSDK` contains orchestration.                                                  |
| Review findings live in a rich JSON response; file optional | The review artifact is canonical and required; JSON is the control envelope.                                      |
| Worker results only through MCP `woof_submit`               | Keep submission validation and idempotence; remove the transport requirement.                                     |
| Reject artifact/file protocols altogether                   | Evaluate publication and acknowledgement semantics; do not reject the user's required artifacts.                  |
| Stashed Claude-only workers and automatic permission bypass | These are implementation proposals, not requirements; capability and permission policies need explicit decisions. |
| Fixed multi-package layout, YAML or fluent workflow API     | Examples illustrate possible shapes; none is a settled packaging or syntax contract.                              |

## Known limits (0.1.x)

Design-level items this release documents rather than fixes. Each row states
current behavior, not an oversight awaiting a quick patch; fixing one would
change a public contract, a trust boundary, or a documented non-goal.

| Limit                                                                                                                                                                                                                                                                                                                                 | Why not in 0.1.x                                                                                                                                                                                   | Direction                                                                                                                                                  |
| ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------- |
| A worker can read or edit its own run's journal and accepted artifacts. The mechanism differs by kind (p8a): a `claude` launch always includes `--add-dir <runDir>`, which is the grant; `pi` has no directory sandbox at all, so it reaches the run directory with the pi process's own permissions and receives no grant to narrow. | Narrowing what a worker can reach is a change to the launch/argument contract for `claude`, and for `pi` it is not an argument problem at all — there is no flag to scope. Neither is a small fix. | Scope `claude`'s `--add-dir` more narrowly, and for kinds with no sandbox rely on out-of-process verification or OS-level confinement, in a later release. |
| A role's `args` may include a permission-bypass flag (for example `--dangerously-skip-permissions`); Woof passes it through with only a warning and never blocks it.                                                                                                                                                                  | Allow-listing or blocking Claude CLI flags is a product policy decision, still open.                                                                                                               | An explicit allow/deny list for role `args`, decided with the operator.                                                                                    |
| A `verify` check (`CheckStage`) runs in the same repository the builder just edited, with no sandbox.                                                                                                                                                                                                                                 | Sandboxing or isolating the verify step is a new execution model, out of this phase's small-item scope.                                                                                            | Run verify in a copy or container in a future release.                                                                                                     |
| Engine-owned run-directory creation checks the last path component against a symlink but not every intermediate component, leaving a narrow TOCTOU window.                                                                                                                                                                            | Closing the race across intermediate components needs a dirfd-based directory walk, a larger change than this phase's small items.                                                                 | A dirfd-based walk, if the race is ever demonstrated exploitable.                                                                                          |
| Four separate paths start a run: `woof run start`, `woof run build-review`, the Herdr plugin's `start` action, and `/woof:run`.                                                                                                                                                                                                       | Unifying start verbs is a CLI/product design decision, not a bug.                                                                                                                                  | Consolidate to fewer verbs once usage patterns are clearer.                                                                                                |
| Some unit tests import compiled `dist/` output in-process rather than only through a real child process; `smoke-package.ts` is the only real-consumer coverage.                                                                                                                                                                       | Restructuring the unit suite around the smoke-package pattern is a test-architecture change, out of this phase's scope.                                                                            | Migrate unit tests that assert public-import behavior to a real-process pattern.                                                                           |
| `journal_write_failed` covers both a `run_dir_invalid`-shaped failure and a lock-acquire I/O error under one reason.                                                                                                                                                                                                                  | A second reason-vocabulary change in one release was rejected — this phase already adds `precondition_failed`.                                                                                     | Split the reason if a consumer is shown to need the distinction.                                                                                           |
| The journal lock's compare-then-unlink release has a dual-accept window after a kill in the release window (C1).                                                                                                                                                                                                                      | Already documented (`v1-evidence.md`'s C1); a flock- or re-read-based redesign is out of scope.                                                                                                    | A flock-based lock, or a re-read-before-unlink check, in a future release.                                                                                 |
| `journal.ts` reads a full journal file into memory, and `exec.ts` concatenates unbounded process output into memory.                                                                                                                                                                                                                  | Caps need sizing decisions (how large a journal or check output is too large) that were not made this phase.                                                                                       | Add a configurable cap once real journal/output sizes are observed.                                                                                        |
| A project workflow module, `--runtime-module`, and role `args` all execute or pass through with the operator's own privileges; configuration-hash computation follows symlinks.                                                                                                                                                       | This is the documented trust model (see the README's Trust model section), not a defect.                                                                                                           | Would need a real sandbox or an explicit lower-trust mode to change.                                                                                       |
| Some timing-based test assertions and production test seams rely on wall-clock behavior.                                                                                                                                                                                                                                              | The two flaky test races this phase fixes are handled by a repeat gate (D11); other timing claims were not independently re-timed.                                                                 | Revisit if a specific test is shown flaky in CI.                                                                                                           |
| A failed `git rev-parse HEAD` is treated the same as "no HEAD yet".                                                                                                                                                                                                                                                                   | Distinguishing the two needs git exit-code semantics that vary across versions; a wrong `repo_invalid` would fail real runs.                                                                       | Add version-checked exit-code handling if a real repository hits this.                                                                                     |
| Check-output evidence can exceed the 1 MiB cap by the header's own length.                                                                                                                                                                                                                                                            | Low-value; not included this phase (lead decision).                                                                                                                                                | Reserve header bytes in the truncation budget.                                                                                                             |
